# 固定旋转装甲靶：实测资料与离线分析

适用工况：17 mm 步兵、名义 3 m、固定中心旋转 4.87 rad/s。
当前只有用户提供的历史约 30% 命中率、粗估指令至出膛约 320 ms；新代码没有实车命中率验收。
资料可稍后提供，先保留完整原件。现场启动和测试由操作员执行。

## 优先提供的数据

| 优先级 | 资料 | 用途 |
|---|---|---|
| 1 | 一次测试的完整程序日志；若有对应录像，一并保留原帧率和起止时间 | 区分请求、发送、实际出弹、漏弹和有效命中，避免仅报百分比 |
| 2 | 一批单发的指令到出膛测量，逐发保留数值、测量方法和同步依据 | 得到延迟中位数及波动，检查约 320 ms 的估计；均值不能代替波动 |
| 3 | 同一距离打静止装甲的弹着照片、标尺、实际发数与有效命中数，最好带每发弹速 | 区分固定偏差、弹道/机械散布与旋转预测问题 |
| 4 | 旋转靶完整每轮实际发数、有效命中数、开始至结束用时；有条件保留逐发对应关系 | 比较完成 31 次有效命中的时间、耗弹以及 50 发内完成情况 |
| 5 | 靶装甲有效尺寸、板数、旋转半径/高度；3 m 的测量起止点；相机型号、实际帧率/曝光 | 核验仿真几何与图像条件，避免把配置值当测量值 |

不必一次准备齐。现有日志、录像和“实际打了几发、有效中了几发、用了多久”最先提供即可。
如果追加采集，单发延迟/静止散布可先取约 20～30 发用于诊断；这不是正式验收样本量要求。
同工况旋转测试按完整轮次保留，获取失败、卡弹、丢目标和超时也记录，不只挑成功片段。
规则中的 30 次/310 血矛盾尚待最终裁判确认；当前离线诊断将 31 次作为明确标注的分析阈值。

## 测量定义

- 当前 `[SHOT_DEBUG]` 用 `(run,id)` 关联请求和 `first_high` 写操作记录。
  请求编号不是弹丸编号；一请求可能不出弹，也可能对应多发。
- `tx_write_complete_ns` 是主机串口写操作完成，不等于下位机收到，更不等于出膛。
  本工具统计这个参考到物理出膛的测量，不能把测得值直接写入预测补偿。
- `fire_flag/fire_tick_ms` 来自电流阈值，尚未独立验证出膛语义；拨弹 RPM、序号和电流波形只作辅助。
- 录像只有在明确拍到可对应的请求参考和实际弹丸出膛时才能量请求到出膛间隔。
  PC 界面显示变化与串口实际写完的偏移未知；不同设备时钟须先同步，禁止直接相减。
  若录像只拍到弹丸，可用于出弹/弹着计数，延迟留空。
- 配置当前写有 150 fps、6 ms 曝光；它们不是实测吞吐或实际曝光中心。
  现有图像时间戳采用主机收帧时刻减配置偏移，仍需要现场时间标定。
- 日志可用现有 `infantry_diagnostics_enabled` 采集诊断；诊断有额外负载，正常和诊断模式不能混作同等时序。
  本轮没有启用诊断、改配置、连接现场或启动实车。

## 已准备的离线工具

已有视觉分析器 `scripts/analyze_prediction_debug.py` 检查同一跟踪段/装甲的未来预测残差，
只衡量视觉一致性，不给实弹命中率。新增 `scripts/analyze_shot_timing.py` 汇总：

- 每轮软件请求写操作的间隔；图像参考/请求发起至主机写完的耗时。
- 外部确认的弹丸数、未知命中标签、同一请求多发以及无法关联的记录。
- 有独立测量时的出膛延迟中位数、5%/95%分位和实测弹速分布。

工具只读取文件。无实测资料时不把请求数当实际发数，不填入猜测的 320 ms，
也不自动改补偿或发射间隔。当前高速请求至少间隔 1000 ms；是否缩短需要可靠出弹数据。

仅看软件时序（路径替换为实际日志）：

```bash
python3 scripts/analyze_shot_timing.py logs/field.log --output logs/shot_timing.json
```

有录像/光电等独立证据后，由分析人员按每个已确认出膛的弹丸填写 CSV，保存在 `data/`，
不用操作员现场手填。表头：

```csv
run,id,projectile_id,tx_to_exit_ms,hit,muzzle_speed_mps,evidence
```

`run,id` 对应日志；`projectile_id` 在同一 run 内唯一；`hit` 为正式有效命中的 1/0，未知留空；
延迟和弹速未测就留空，`evidence` 填原始录像时间段/测量文件及同步方法，不能写成猜测。
确认已出膛但没找到请求的记录先保存原始证据，不能猜配编号。
`tx_to_exit_ms` 必须与本工具的主机写完参考一致；只有其他起点的测量应单独保留，不混入此列。
一请求多发逐弹分行，不能只写一行代表多发；没有出膛的请求不填成“未命中弹丸”。

```bash
python3 scripts/analyze_shot_timing.py logs/field.log --observations data/field_projectiles.csv --output logs/shot_timing.json
```

完全相同的重复记录只算一次，冲突的同编号记录排除并列出；未知命中不算作未中。
只有外部样本全部有标签时，才给该样本的比例，仍不能证明整轮没有漏标弹丸。
输出包含输入哈希和关联问题，完整原件仍需人工核对。不得从该工具自动推算整车新命中率。

后续优化顺序：先量时序和静止散布，再用旋转日志检查同板预测、云台跟随及丢失；
最后在拨弹稳定范围内比较请求间隔，按完整轮次同时比较完成时间和有效命中。
单纯放宽开火门限或降低间隔可能增加弹耗，不能据请求变密就判定完成更快。
